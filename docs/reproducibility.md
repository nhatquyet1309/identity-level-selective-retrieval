# Reproducibility record

Checkpoints, preprocessing, index, seeds and manifests of the analyses in this repository. Items that could not be established from the stored artifacts are marked NEEDS VERIFICATION with the reason.

The work is reproducible from the released artifacts up to the item listed below as not determined. Each item gives a value or is marked [NEEDS VERIFICATION] with the reason.

- Checkpoint / model id. SigLIP2-I: google/siglip2-so400m-patch14-384 (encoder_id siglip2-so400m-patch14-384, embedding dimension 1152). CLIP-B-I: clip-vit-b32 (dimension 512).
- Checkpoint revision. SigLIP2-I: google/siglip2-so400m-patch14-384, snapshot e8e487298228002f3d8a82e0cd5c8ea9c567f57f (read from refs/main of the model cache on the server; the weight file model.safetensors was re-hashed, sha256 9f4f4a49f908ef0c979bce8ff5a5c0e88882dc6c5dc4304387cbbd152558e2c2). It is the only snapshot in the cache and no other HF_HOME exists, so it is the one loaded; no run log records the loaded revision directly, hence this is a strong inference, not a direct record. CLIP-B-I: the OpenAI clip package, ViT-B/32, weight file ViT-B-32.pt with sha256 40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af, equal to the hash in the download URL of the package.
- Preprocessing. SigLIP2-I: the image is resized to 384 × 384 with the BILINEAR filter (resample = 2 in the preprocessor configuration), with no crop, and normalised with mean = std = 0.5. CLIP-B-I: Resize(224, BICUBIC) of the shorter side followed by CenterCrop(224). The crop expansion is expand(b, 15%) of the detector box.
- Normalization. Embeddings are L2 unit-norm; the stored CLIP index (1667 vectors, dimension 512) was checked after the fp32 rebuild (D8): every norm is within 1e-6 of 1.
- Index. FAISS IndexFlatIP (exact inner-product search over L2-normalised vectors; faiss 1.15.1, torch 2.14.1+cu130, numpy 2.2.6, PIL 12.3.0, Python 3.10.12 on the server): 1667 × 1152 for SigLIP2-I and 1667 × 512 for CLIP-B-I, read with faiss.read_index. In v9 the identity scores are computed in numpy from the stored vectors, so the index is the vector store.
- Package clip commit. Not determined. [NEEDS VERIFICATION] The commit of the clip package installed in the server environment cannot be read (only clip_version 1.0 appears in an outdated manifest, and the installed package has no git metadata).
- Mapping M. The oracle coarse class maps to the candidate set Y_c through the mapping M (8 gallery categories, 6 coarse classes, n_c in {2, 10, 15, 18, 19, 36}; artillery, air-defence and missile are grouped into the vehicle class); M changed between ab3 and ab4 (R-D9), and ab4 is the registered run.
- Temperature T. T is chosen once on calibration over {0.01, 0.02, 0.05, 0.1, 0.5, 1} by the argmin of E-AURC; T* = 0.01 (lower edge of the grid) for every sealed cell and is not re-selected in the post hoc analyses.
- Ties. Argmax ties are resolved by identity name in stable order (smallest index in the Y_c label regime); rankings use a stable mergesort in input order and AUROC uses mid-ranks for ties.
- Manifests. The ab4 split manifest (split.json), the Tier B transforms manifest (transforms_manifest.csv, SHA-256 per transformed file), the capture metadata files of the v9 passes and the near-duplicate component list are stored with the results.
- Near-duplicates. Near-duplicates are merged as connected components at cosine 0.98 (sensitivity 0.95; perceptual-hash distance cap 4), listed in the component file; each query masks its own component.
- SHA-256. Every result folder carries a SHA256SUMS file; protocol v7 was sealed on 17 Nov 2026 (SHA-256 e5080142…) and protocol v9 on 21 Nov 2026 (SHA-256 2e0246c9…); the transform script hash is given in section 7.
- Deviations. D1 to D13 are in the deviation log released with the code; D14 to D20 are listed in section 11. D13 is the sensitivity analysis over Y_c; D20 is Tier B.
- Lost images. 171 of 790 ab4 index images could not be recovered (D11), which gives the 619-image index of Tier C.
- A-50. The v8 row-2 source A-50 of the qualitative figure (row 2 is replaced, section 12) was excluded after its trial-run scores were seen, because the gallery mislabels it (A-50 for an E-3); the selection rule is stored with the figure results. The mislabelled gallery entry is still to be corrected by the data owner.
- Bootstrap seed. The first cluster bootstrap of the P1 analysis of round v9 used a per-process string hash as the auxiliary seed and was not reproducible bit by bit (D13, deviation log item 5). It was rerun deterministically (D22): the auxiliary seed is derived from zlib.crc32 of the encoder and comparison tag, with the main seed unchanged, so the CIs and p values are the same in every process. All six labels (6 of 6) are unchanged; the largest CI shift against the first run is 0.0019. The new CIs match the D13 run (same tag). The original sealed result file p1_results.json is kept unchanged.
- Software of the new analyses. D14 to D20 were computed locally with Python 3.11 and numpy only, by the scripts v9rev_<name>.py, with seed 20261022.
